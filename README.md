# EVE 启动器更新加速器

EVE Online 启动器更新太慢时用的小工具，能做三件事。

1. **换节点** — 给更新用的域名挑一个离你最近的 CDN 节点写进 hosts，而且当场验证过它真能下东西
2. **掉速诊断** — 告诉你慢的原因到底是节点差、线路拥堵，还是**按连接限速**
3. **并发预下载** — 如果是按连接限速，多线程把缺的资源文件直接下进 EVE 缓存，启动器打开就跳过

纯 Python 标准库实现，**零第三方依赖**；全程只用 IPv4；hosts 只动自己那一段，随时可还原。

## 功能

```
[1] 一键加速     检测 → 验证 → 测速 → 写 hosts → 复检
[2] 只检测       只看哪个节点最快，不动 hosts
[3] 还原 hosts   删除本程序写入的加速段
[4] 查看状态     当前 hosts 里的加速条目 / 备份
[5] 打开配置     编辑要加速的域名列表
[6] 掉速诊断     下载会掉速时用：判断是按连接限速还是线路拥堵
[7] 并发预下载   多线程把缺的资源文件下进 EVE 缓存，启动器直接跳过
```

命令行：`--apply` / `--test` / `--restore` / `--status` / `--diagnose` / `--predownload [--yes]` / `--no-pause`

---

### 1. 换节点：为什么不会像网上抄来的 hosts 那样"改完反而下不动"

那些 hosts 里的 IP 只是"某个时候能 ping 通"，可能早就过期，可能是别家站点的边缘节点，
也可能连得上却对 EVE 的文件返回 403/404。本程序写进 hosts 的每个 IP 都必须**当场**通过：

| 关卡 | 做什么 | 挡掉什么 |
|------|--------|---------|
| 1. TCP | 443 能连上 | 死 IP |
| 2. TLS | 用域名做 SNI，**强制校验证书链和主机名** | DNS 污染和劫持，还有别家站点的 IP（证书伪造不了） |
| 3. 真实文件 | 从 EVE 官方索引取**当前版本正在用的更新文件**下载 | 能握手但不给 EVE 文件的节点 |
| 4. 内容比对 | 多节点交叉比对哈希 / ETag / 长度，只留和多数一致的 | 内容错误、缓存脏了的节点 |
| 5. 粗测 | 每个候选短测 3 秒 | 根本下不动的 |
| 6. 持续测速 | 领先的几个各下最多 12 MB，**前 3 MB / 前 2 秒算起步不计入** | 起步猛、几 MB 后掉到几十 KB 的节点 |
| 7. 写入前复查 | 写之前再确认一次，不行就换排名第二的 | 这期间节点状态变了 |
| 8. 落地复检 | 写完刷新 DNS 后**再验一次真实下载**，带重试 | 万一还是出问题 |

第 3 关是关键。程序读 `binaries.eveonline.com/eveclient_TQ.json` 拿到当前 build，
再读 `eveonline_<build>.txt` 和 `resfileindex.txt` 两个官方索引，从里面挑真实更新文件当靶子。
所以"验证通过"= **这个节点确实能把 EVE 的更新文件原样发给你**。

复检没过的域名会被**单独摘掉**，其它域名的加速照常保留；只有全部失败才完全回滚。

候选节点从哪来：多路 DoH（阿里 / DNSPod / Cloudflare / Google / Quad9 / OpenDNS，带 ECS）
+ 国内外 UDP DNS + 系统解析，再加上对 Cloudflare 公开任播段的就近扫描。
`binaries` / `resources` 都在 Cloudflare 后面，DNS 只会给两三个 IP，扫描能把候选池扩到 15 个以上。

### 2. 掉速诊断

遇到"刚开始几 MB 很快，然后掉到几十 KB"就用 `[6]`。它会单连接连下 20 秒画出每秒速度曲线，
立刻新开一条连接对比，最后看 4 条并发能不能把总吞吐叠上去：

```
  单连接每秒速度：
    第  3 秒  442 KB/s    ################################
    第 10 秒  141 KB/s    ##########
    第 19 秒  45 KB/s     ###
  起步 3 秒平均 312 KB/s，最后几秒平均 95 KB/s
  新连接速度 296 KB/s
  4 条并发合计 995 KB/s（单条约 249 KB/s）

典型的【按连接限速】：一条连接下几 MB 之后被压下去，新开连接又满血。
并发有明显收益：4 条合计 995 KB/s，是单条掉速后 95 KB/s 的 10.5 倍。
```

| 诊断结果 | 该怎么办 |
|---------|---------|
| 按连接限速 | 换节点收益有限，**用 `[7]` 并发预下载** |
| 线路整体拥堵 | 换节点只能挑相对最快的；错峰或走代理 |
| 全程稳定 | 慢的原因在启动器自身（磁盘、杀毒实时扫描） |

### 3. 并发预下载

官方启动器是单线程下载，遇到按连接限速就只能干等。但 EVE 的资源文件是内容寻址的：

```
<SharedCache>/ResFiles/<两位>/<hash>_<md5>
```

文件名里就带着 md5。所以我们可以自己开多条连接把缺的文件下好放进去，
启动器再去更新时发现本地已有，直接跳过，这等于把单线程下载换成了多线程。

- SharedCache 位置自动探测（Windows 读注册表 `HKCU\Software\CCP\EVEONLINE\CACHEFOLDER`，
  再退回启动器日志和常见路径；也可以在配置里手填 `shared_cache`）
- 先和本地缓存做差集，只下缺的，并在开始前告诉你**缺多少个、共多大**，你确认了才下
- 每个文件校验 md5 和大小，**先写临时文件再原子改名**，绝不覆盖已有文件、绝不写出半个文件
- 长连接复用 + 定期重建，中途 Ctrl+C 可以停，已下好的都留着，下次接着下
- 只碰 `ResFiles` 里的资源文件，不动客户端本体

## 加速哪些域名

| 域名 | 作用 |
|------|------|
| `binaries.eveonline.com` | 客户端/启动器二进制、更新索引 |
| `resources.eveonline.com` | 客户端资源文件（更新流量的大头） |
| `launcher.eveonline.com` | 启动器配置/自更新 |
| `web.ccpgamescdn.com` | 可选，找不到可验证路径就自动跳过 |
| `login.eveonline.com` | **默认不动**（登录域名钉死有风险，要加就把配置里 `enabled` 改 `true`） |

域名列表和测速参数都在程序同目录的 `eve_accel.json` 里，可自行修改。

## 安全性

- hosts 只在 `# ==== EVE-ACCEL BEGIN ====` 和 `# ==== EVE-ACCEL END ====` 之间写东西，
  你自己的其它行一个字节都不动（做过字节级测试）。
- 备份只留一份：Windows 在 `%LOCALAPPDATA%\EVEAccel\hosts_backup.txt`，
  每次修改前覆盖，内容永远是"去掉加速段之后"的你的原始 hosts。
- 复检不过会摘掉对应域名，全败则完全回滚。手工还原也很简单：删掉那两行标记之间的内容。
- 预下载只新增文件、只写 `ResFiles`，md5 不对的直接丢弃不落盘。

## 常见问题

**测速结果全都很低**
先确认 EVE 启动器/客户端没在后台下载。它会和测速抢带宽，把所有节点一起拉低。程序检测到 EVE 进程时会提醒。

**某个域名提示"复检不通过，已摘掉"**
那个节点写入后不行了（CDN 调度变了，或运营商对这个 IP 限速）。其它域名的加速仍然有效，重跑一次会换别的节点。

**提示检测到 IPv6**
hosts 只能改 IPv4。如果网络有 IPv6，启动器可能走 AAAA 记录绕开加速；可在网络适配器属性里临时取消勾选 IPv6。

**杀毒软件报毒 / macOS 打不开**
PyInstaller 单文件程序没有代码签名，被启发式拦截很常见。介意就直接跑源码。

**EVE 更新大版本后还能用吗**
能。索引缓存里的路径会先做有效性检查，失效就自动重新抓官方索引。

## 声明

本项目与 CCP Games 无关。它只做这些事：查 DNS、验证节点，测一遍速度，往 hosts 写几行，
再把官方 CDN 上的资源文件下载到官方缓存目录里。不修改游戏文件，不注入进程，随时可还原。
